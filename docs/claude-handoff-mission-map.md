## 지도 상세 동작

- 지도 높이 초안: 270px. 외부 카드 패딩 14px / 모서리 22px, 지도 모서리 16px.
- 헤더 오른쪽: `{방위}쪽 · 직선 {거리}`. 1km 미만은 10m 반올림, 이후 소수점 한 자리 km.
- 거리와 방위는 기존 `haversineMeters`, `bearingDeg`, `directionFromHeading`으로 단말 내 계산한다. 도보 거리·경로 계산이 아니다.
- 기존 지도 구현의 출발점→선택 핀 점선을 재사용한다. `점선은 방향 표시예요. 실제 길은 길찾기에서 확인하세요`를 표시한다.
- 결과 지도는 선택 장소 1개만 전달한다. 핀 탭/빈 지도 탭으로 목적지 선택이 해제되지 않게 했다. 사진 프리뷰는 중복이므로 숨긴다.
- 출처 `출처: ⓒ한국관광공사`를 지도 카드 아래 표시하며 카카오/OSM 지도 제공자 표기는 유지한다.
- SDK 로더는 실패 후 재호출이 가능한 기존 로직이다. 재시도는 MapView만 remount한다.
- 좌표 유효성은 유한 수·위경도 범위·(0,0) 여부를 검사한다. 잘못된 기준점과 잘못된 목적지 안내가 같은 문구인 점은 개선 가능하다.

## 남은 검토·검증 (완료로 간주하면 안 됨)

1. **브라우저 시각 검증:** 280/320/390/480px에서 미션 카드 전체, 글자 잘림·캐릭터 겹침·가로 넘침·하단 내비 가림을 확인하고 스크린샷을 남긴다. 긴 날짜별 미션도 확인한다. 현재 미션 줄 제한 3줄이 실제 문구를 과하게 자르면 제거/조정한다.
2. **실제 SDK 확인:** 로컬 도메인 허용과 기존 키 설정을 확인한다(키 값 출력 금지). 카카오 타일·핀·범례·줌·전체 보기 동작을 실제로 확인한다. SDK 실패를 강제한 기본 지도 상태도 별도 확인한다. SDK 성공 검증 없이 '카카오맵 검증 완료'라고 쓰지 않는다.
3. **범위 맞춤:** 두 핀이 한 화면에 들어오는지, 핀 라벨과 우측 컨트롤이 겹치지 않는지 확인한다. 아주 가깝거나 같은 좌표, 멀리 떨어진 기준점, 좁은 화면을 포함한다. LocalMapView는 부산 원도심용 벡터 지도이므로 먼 좌표를 의미 있게 표시하는 데 제한이 있다.
4. **기준점 일관성:** `App.tsx`의 `fieldOrigin` 수명과 `SpinScreen`의 `onFieldOriginChange`를 읽어 스핀→리빌→결과 이후에도 추천에 사용한 origin이 유지되는지 확인한다. 현장/여행 전환, 직접 명소 상세 진입에서도 잘못된 GPS 라벨이 남지 않아야 한다. 필요하면 추천 시점 기준점의 스냅샷을 결과 상태에 함께 보관한다.
5. **결과 흐름:** 실제 스핀→공개→결과→다른 후보→다시 돌리기를 확인한다. 관광지·음식점·카페·테마 결과 모두 확인하고 지도가 오래된 후보에 머무르지 않는지 본다. 사진 확대와 기존 길찾기·공유를 회귀 확인한다.
6. **접근성/스크롤:** 지도에서 손가락을 움직일 때 카드 스크롤이 불편하지 않은지, 44px 터치 영역·모션 감소·키보드 포커스를 확인한다. 페이지 런타임 오류도 확인한다.
7. **공용 지도 회귀:** compactOverview 기본값은 false다. 명소 탭·코스·출발점 선택 지도의 기존 범위 맞춤과 선택 팬이 유지되는지 확인한다.
8. **마무리:** 필요한 동작 테스트와 check/build 실행, 문서의 새 검증 결과 기록, diff 확인 후 이 작업 파일만 커밋한다. 배포는 이 인계 작업 범위가 아니다.
