## 2. 서비스 소개 문안 (글자 수별)

양식의 입력란 길이에 맞춰 고른다. 모두 같은 내용을 길이만 달리한 것이다.

### 한 줄 소개 (41자)

```
휴대폰을 돌려 정한 방향으로 부산 원도심·영도의 숨은 관광지를 찾는 서비스
```

### 100자 내외 (101자)

```
휴대폰을 돌려 방향을 정하면 부산 원도심·영도의 관광지를 추천합니다. 한국관광공사 TourAPI를 실시간 호출해, 대표 관광지에 쏠린 방문을 골목·시장·근현대 유산으로 분산시킵니다.
```

### 300자 내외 (293자)

```
Spindle은 휴대폰을 돌려 방향을 정하는 스핀으로 다음 목적지를 고르는 관광 분산형 탐색 서비스입니다.

해운대·광안리 같은 대표 관광지에 집중된 방문 수요를, 부산 원도심과 영도의 골목·시장·근현대 문화유산으로 흘려보내는 것이 목적입니다. 스핀이 방향을 정하면 추천 엔진이 그 방향 안에서 접근 가능성·운영 상태·인지도를 평가해 덜 알려진 장소에 더 높은 가중치를 줍니다.

한국관광공사 TourAPI 두 개 서비스를 실시간 호출하며, 사용자 GPS 좌표와 방위각은 단말 밖으로 나가지 않습니다.

출처: ⓒ한국관광공사
```

### 1,000자 이내 (912자) — 설명란이 긴 경우

```
Spindle은 휴대폰을 돌려 가리키는 방향의 부산 원도심·영도 관광지를 추천하는 관광 분산형 게임 탐색 PWA입니다.

■ 해결하려는 문제
한국관광 데이터랩의 2021년 부산 방문객 조사에서 "가장 기억에 남는 지역"은 해운대해수욕장 58.4%, 광안리 31.7%, 자갈치시장 31.5%였습니다. 부산 관광의 기억이 소수 대표지에 강하게 몰려 있습니다.

■ 접근 방법 — 왜 "방향"인가
첫째, 몸의 행동이 결과를 만듭니다. 실제로 겨눈 방위가 그대로 알고리즘 입력이 되어, 연출 각도와 계산 각도가 분리되지 않습니다. 둘째, 방향은 분산의 자연스러운 단위입니다. 늘 가던 쪽이 아닌 방위가 나오면 설득 없이도 동선이 흩어집니다. 셋째, 부산 원도심에서는 방향이 곧 지형입니다. 같은 500m라도 영도대교를 건너느냐 산복도로를 오르느냐에 따라 경험이 달라지므로, 다섯 개 생활권 존과 교량·지하철·버스 경유 비용을 반영한 접근성 모델을 만들었습니다.

■ 공공데이터 활용
국문 관광정보 서비스(KorService2)의 areaBasedList2·detailCommon2·detailIntro2·detailImage2·searchFestival2로 관광지 목록과 상세·사진·축제를, 관광지 집중률 예측 서비스(tatsCnctrRatedList)로 당일 예상 집중률을 실시간 조회합니다. 집중률은 명소 지도에 "오늘 혼잡 예상" / "오늘 가기 좋아요"로 표시해, 분산이라는 목적을 사용자가 눈으로 확인하게 합니다.

■ 개인정보와 데이터 취급
계정·로그인이 없고 개인정보를 수집하지 않습니다. GPS 좌표와 방위각은 단말 안에서만 계산하며 어떤 서버로도 전송하지 않습니다. 좌표 기반 엔드포인트를 쓰지 않고 지역코드 기반으로만 조회하며, TourAPI 응답은 세션 메모리에만 두고 영속 저장하지 않습니다.

출처: ⓒ한국관광공사
```

## 3. 활용한 공공데이터 (양식에 목록란이 있을 때)

제공기관은 모두 **한국관광공사**다.

| 서비스 | 엔드포인트 | 용도 |
|---|---|---|
| 국문 관광정보 서비스(KorService2) | `areaCode2` | 부산과 4개 구 지역코드 확인 |
| | `areaBasedList2` | 대상 4개 구의 관광 POI 목록 |
| | `detailCommon2` | 관광지명·주소·개요·대표 이미지 |
| | `detailIntro2` | 이용시간·휴무·요금·주차 등 방문 정보 |
| | `detailImage2` | 대표 이미지가 부족한 장소의 추가 이미지 |
| | `searchFestival2` | 지역·날짜 기준 축제·행사 |
| 관광지 집중률 예측 서비스 | `tatsCnctrRatedList` | 당일 예상 집중률 (혼잡·쾌적 표시) |

**실시간 호출 방식**이며 로컬 DB·파일에 적재하지 않는다. 상세 근거는 기능설명서 5.3장.
