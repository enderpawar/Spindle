# Phase 7 테마 목록 이미지 복구 — 2026-09-07

기존 테마 덱의 이미지 실패 처리 보완. 선행 Phase 1–6 완료 상태를 확인했다.
PLAN.md·SPEC.md·docs/ui.md에는 다른 작업의 미커밋 변경이 있어 해당 파일을 수정하지 않고 이 문서에 변경 명세와 검증 결과를 기록한다.

## 확인한 원인

- 로컬 개발 서버의 기존 프록시로 두 장소의 상세·이미지 API를 실시간 확인했다.
- 부산 송도해수욕장: 대표 썸네일은 HTTP 404, 대표 원본과 별도 갤러리 썸네일은 HTTP 200.
- 국제시장: 대표 사진이 없고 추가 이미지 목록도 비어 있다. 로딩 실패와 구분해야 한다.
- 기존 썸네일 함수는 조회 실패를 null로 변환한 뒤 세션에 계속 저장했다. 기존 사진 컴포넌트는 이미지 파일 오류 시 대체 URL을 시도하지 않았다.

## 변경 명세 (SPEC.md §5 이미지 / docs/ui.md 테마 덱 보완)

- 목록에서 얻은 썸네일을 먼저 사용한다. 파일 로딩 실패 시 같은 장소의 알려진 원본·썸네일 중 실패하지 않은 URL을 시도한 다음 detailImage2의 다른 사진을 조회한다.
- 대체 사진도 썸네일을 우선하며, 실패 URL·중복 URL·시설 전용 사진을 제외한다. 카드당 대체 시도는 최대 3회다.
- 이미지 URL 조회 실패는 캐시에서 제거하고 현재 카드에서 1초 후 한 번 재시도한다. 정상적인 사진 없음 결과는 메모리 캐시를 재사용한다.
- 공통정보 호출만 실패해도 병렬 사진 호출이 성공하면 그 사진을 사용한다.
- IntersectionObserver로 화면 근처에 들어온 카드만 활성화하고, 활성화한 img는 추가 lazy 대기 없이 불러온다. 장소·사진 크기 변경 시 로딩/실패 상태를 초기화한다.
- 사진이 없는 장소는 기존 테마 배경과 아이콘을 유지한다. 사진을 임의 생성하거나 다른 장소 사진으로 대체하지 않는다.
- 모든 응답은 세션 메모리에만 보관한다.

## 조회 로직 후속 개선

- 목록 워밍업 상한을 2,500ms에서 300ms로 축소했다. 페이지별 색인 변경을 구독하여 해당 장소가 도착하면 다른 지역·다음 페이지의 완료를 기다리지 않는다. 종료 시 구독과 타이머를 정리한다.
- 공통정보와 추가 사진 중 먼저 도착한 유효 URL을 사용한다. 빈 응답은 다른 요청의 성공을 가리지 않으며, 모두 비어 있을 때만 사진 없음으로 확정한다.
- detailImage2의 진행 중 Promise와 성공 응답을 대표 사진·썸네일·대체 사진·갤러리가 공유한다. 원본과 썸네일 선택 결과는 분리하여 작은 카드에서 원본 캐시를 잘못 재사용하지 않는다.
- 목록 외 상세 폴백에서도 firstimage2/smallimageurl을 우선 사용한다. 갤러리는 공통정보·추가 사진을 동시에 요청하며 부분 실패를 영구적인 빈 갤러리로 저장하지 않는다.
- UI용 조회 결과를 ready/empty/error로 구분하여 error에만 자동 재시도를 건다. 기존 URL/null 반환 함수는 기존 호출부와 호환을 유지한다.
- 대기 상한 축소는 빠른 상세 조회 시작을 위한 절충이다. 목록이 300ms보다 늦으면 기존보다 상세 API 호출이 늘 수 있지만 동일 장소의 동시 요청은 공유한다. 전체 실기기 로딩 시간의 개선 수치를 측정한 것은 아니다.

검증: API 관련 78개 테스트, 전체 web 382개 + proxy 26개 테스트, 타입 검사·lint·guard·프로덕션 빌드 통과. 미응답 공통정보 뒤 사진 반환, 부분 페이지 조기 종료·타이머 정리, 300ms 상한, 동시 호출 공유, 상태 구분·부분 실패 복구를 회귀 테스트로 확인했다. 브라우저·실기기 검증 항목은 위와 같이 미완료다.
