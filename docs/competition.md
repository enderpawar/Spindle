## 핵심 규정 (FAQ 확인 사항)

1. **TourAPI 실시간 호출 방식 권고.** FAQ 원문: "한국관광공사 OpenAPI 서비스는 데이터 동기화 오류 방지를 위해 로컬 DB 저장 방식이 아닌 실시간 호출 방식으로 활용하실 것을 **강력히 권고**드립니다." → 금지가 아니라 권고이며, 사유도 규정이 아니라 데이터 신선도다. 파일 데이터는 불인정. Spindle은 실시간 호출로 설계.
   - FAQ는 이어서 "로컬 DB 저장 방식을 사용하여 서비스 개발 기간 내 API 호출 이력이 확인되지 않을 경우, 심사에서 불이익"이라고 하고, 부득이하게 로컬 DB를 써야 하면 **별도 신청서**를 tourapi@knto.or.kr로 문의하라고 한다. Spindle은 해당 없음.
   - **캐시를 쓰지 않기로 한 근거(2026-09-07)**: ① 권고를 거스를 실익이 없다 — 예열을 "곧 보여줄 대상"으로 옮기는 것만으로 세션당 `detailIntro2`가 54회 → 5~7회가 되어 트래픽 문제가 캐시 없이 해결된다. ② 아래 규정 2번의 **인증키 호출 이력 검증**은 권고가 아니라 실제 검증 항목인데, 캐시는 그 이력을 줄이는 방향이다. ③ 프록시 경유의 "실시간 호출" 인정 여부(질의 ②)가 미해결인 상태에서 프록시에 TTL 캐시를 얹으면 리스크가 커진다. → 공모전 이후 실서비스로 전환한다면 엣지 캐시(Workers KV 등)가 1순위가 되며, 지금 만든 지연 호출 구조는 캐시 미스 경로로 그대로 남는다.
2. **제출한 인증키로 개발 기간 중 실제 호출 이력을 검증** → 개발 첫 주부터 운영계정 키 사용.
   - 제출 기준(Notion 제출항목 4번): 활용 API별 **신청자 인증키(인코딩·디코딩 키) 일체는 필수**, 대표 1개 API의 **운영계정 신청은 선택**. Spindle은 KorService2와 관광지 집중률 예측 서비스 **두 서비스의 키를 모두** 제출한다.
3. 생성형 AI 사용에 따른 감점 없음 (서비스 기능 내 AI 접목·코딩 보조 도구 모두 제한 없음).
4. 웹 서비스는 URL 제출로 심사 (앱스토어 등록 불필요). 서비스 형태(웹/앱)는 심사에 영향 없음.
5. **서비스 소유권은 참가자에게** 있으며 공사는 개발 서비스를 운영하지 않는다. 개발 서비스 내 "한국관광공사", "KTO" 등 공사를 지칭하는 단어·로고로 공사가 직접 개발·운영하는 것처럼 오인시키는 표기는 금지(FAQ 원문은 "단어/로고 사용 금지"). 공식 CI/BI 로고 이미지는 무단 사용 불가.
6. **공공데이터 출처 텍스트 표기는 필수.** `출처: ⓒ한국관광공사` 또는 `출처: ⓒ한국관광콘텐츠랩`으로 표기한다. `TourAPI`만 단독 출처로 표기하는 방식은 지양. FAQ가 "단순 데이터 출처 명시 목적의 기관명 표기는 필수 사항이며, 금지 대상에 해당하지 않습니다"라고 5번과의 충돌을 명시적으로 풀어 두었다.
7. **기능설명서는 반드시 제공된 공식 양식으로 작성해 PDF로 제출한다.** 원문: "임의 양식 활용 시 심사 대상에서 제외될 수 있습니다", "양식 내 필수 작성 항목을 임의로 누락/변경하였을 경우 심사 대상에서 제외될 수 있습니다." 양식 목차는 아래 "기능설명서 공식 양식" 절. `docs/submission/기능설명서.md`는 자체 구성이므로 **내용을 양식에 옮겨 적어야 한다.**
8. **TourAPI 외 API 사용은 허용된다.** 외부 API를 금지·제한하는 조항은 공고·FAQ·OT 자료 어디에도 없고, 공식 양식에 "5. [선택] 데이터 활용(기타) — 서비스 개발에 활용한 기타 API, 파일데이터" 칸이 따로 있다. 카카오맵 JS SDK는 이 칸에 적는다.
9. **법적 책임은 지원자에게 있다.** 원문: "공모전 참여를 위한 제출서류, 공모작 등 초상권, 저작권, 표절 등 관련 법적인 문제가 발생할 경우, 모든 책임은 지원자에게 있습니다." → 카카오맵 등 외부 API의 약관·운영정책 준수도 스스로 책임진다.
10. 서비스 유형(웹·앱·SW 등)을 두 종류 이상으로 개발할 경우 **반드시 동일 내용의 서비스**여야 한다. Spindle의 웹·iOS·Android는 같은 번들이라 해당 없음.
11. 동일 서비스로 본 공모전 수상 또는 공사 주관 지원 사업(서비스 개발·구축지원) 수혜 이력이 있으면 심사 제외. 제출 내역이 허위이거나 결격 사유가 있으면 평가 제외·수상 취소·상금 회수.

- **현재 위치 지도·심사용 조이스틱 점검(2026-08-02)**: 활성 안내는 카카오맵 베이스맵을 사용하되 실제 GPS를 Spindle 서버·프록시·로그로 전송하지 않고, 베이스맵 카메라와 타일 범위도 공개 관광지 목적지를 기준으로 유지한다. 현재 위치와 활성 구간선은 클라이언트 오버레이로만 갱신한다. `?demo=1` 조이스틱은 실제 위치 권한을 호출하지 않고 가상 좌표를 세션 메모리에서만 변경하므로 카메라 추종을 허용해도 개인정보·TourAPI 호출 이력에 영향을 주지 않는다.
- **자체 경로안내 폐기 결정(2026-08-02)**: 앱 내 턴바이턴·방위 화살표 안내를 제공하지 않기로 확정하고 관련 코드(`CourseGuideScreen`, `engine/courseGuidance`, demo GPS 조이스틱)를 제거했다. 실제 도로 경로를 받으려면 사용자 현재 좌표를 라우팅 API(카카오모빌리티·T맵 등) 출발지로 전송해야 하는데, 이는 절대 원칙 1 위반이며 위 FAQ 기준상 "서버로 전송 → DB 저장 여부와 무관하게 신고 대상"에 해당해 비신고 구조가 깨진다. Kakao Maps JS SDK에는 경로 탐색 기능이 없고 카카오모빌리티 길찾기는 REST 키가 필요한 별도 서버 API라 클라이언트 직접 호출로도 우회할 수 없다(절대 원칙 4). 결과적으로 코스 흐름에서 `watchPosition`·DeviceOrientation을 전혀 사용하지 않게 되어 좌표 무전송이 구조적으로 자명해졌다.
